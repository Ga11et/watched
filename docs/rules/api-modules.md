# Структура модулей API

Правило действует для модулей в `packages/api/src/<модуль>/`. Папки `common/` и `database/` и клиент в него не входят.

## Файлы модуля

Имя файла начинается с имени папки модуля: `users/users.service.ts`.

| Файл                            | Содержимое                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<модуль>.module.ts`            | Nest-модуль: импорты, провайдеры, контроллеры.                                                                                                                   |
| `<модуль>.controller.ts`        | Маршруты, Swagger, привязка DTO и вызов сервиса. С БД работает только через сервис.                                                                              |
| `<модуль>.service.ts`           | Сценарии: чтение, создание, обновление, удаление, транзакции и преобразование в DTO ответа.                                                                      |
| `<модуль>.policy.ts`            | Решения о доступе: чистые функции `can…(actor, …)` без обращений к БД. Их вызывают контроллер и сервис.                                                          |
| `<модуль>.rules.ts`             | Проверка данных модуля: нормализация, формат, проверки занятости в БД только на чтение и перевод ошибок ограничений БД в 422.                                    |
| `<модуль>.types.ts`             | Типы, которыми пользуются несколько файлов модуля или другие модули. Тип, нужный одному файлу, объявляется в этом файле.                                         |
| `entities/<сущность>.entity.ts` | Сущность TypeORM и enum её колонок. Имя сущности в единственном числе.                                                                                           |
| `dto/<класс>.dto.ts`            | Классы тела запроса и ответа с декораторами class-validator и Swagger. Один класс на файл, имя файла по классу: `ChangeUserRoleDto` → `change-user-role.dto.ts`. |

Инфраструктура Nest называется `<имя>.<тип>.ts`: `auth.middleware.ts`, `roles.guard.ts`, `api-exception.filter.ts`, `jwt.service.ts`.

Файл появляется вместе с первым содержимым: у модуля без правил доступа нет `<модуль>.policy.ts`.

## Применение

Новые и изменённые файлы следуют правилу. Остальные файлы модуля приводит задача [#52](https://github.com/Ga11et/watched/issues/52).

## Известные отклонения

Удаляйте пункт, когда отклонение исправлено:

- `users/user-access.policy.ts` вместо `users/users.policy.ts`.
- Общий тип `AuthUser` объявлен в `auth/auth.middleware.ts` вместо `auth/auth.types.ts`.
- Общий тип `JwtPayload` объявлен в `auth/jwt.service.ts` вместо `auth/auth.types.ts`.
- Несколько классов в одном DTO-файле: `users/dto/update-user.dto.ts` (2), `user-lists/dto/user-list.dto.ts` (8).
- `users/users.controller.ts` проверяет роль `ADMIN` прямо в коде (4 места) вместо функций политики.
