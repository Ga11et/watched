# Проверка фронтенда

Правило действует для `packages/client/` и не ограничивает unit/E2E-тесты API.

## Проверки агента

Не добавляйте и не запускайте unit/E2E-тесты фронтенда. Используйте статические проверки,
сборку и простой smoke без браузерной автоматизации и подробных UI-сценариев:

1. Проверьте изменённые файлы Prettier.
2. Выполните `pnpm --filter client lint`: команда подготавливает конфигурацию Nuxt и запускает
   ESLint для JavaScript, TypeScript и Vue без автоисправлений. Сгенерированные файлы и результаты
   сборки исключены из проверки; форматирование остаётся за Prettier.
3. Выполните `pnpm --filter client typecheck`: команда подготавливает типы Nuxt и запускает
   `vue-tsc --noEmit` для проверки типов TypeScript и Vue-компонентов без генерации файлов.
4. Выполните `pnpm --filter client build` для проверки сборки; она не заменяет проверку типов.
5. Проверьте запуск приложения и HTTP-доступность страницы простым запросом.
   Успешный ответ не подтверждает корректность интерфейса и пользовательских сценариев.

## Проверка интерфейса

После работы над задачей разработчик вручную проверяет интерфейс и затронутые сценарии.
В итоговом сообщении перечислите выполненные проверки, их результаты, ограничения и
сценарии, которые разработчику нужно проверить вручную.
