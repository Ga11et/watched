# Тесты

Правило действует для всего репозитория.

## Периметр

- Тестируется только бэкенд `packages/api/`. Для `packages/client/` действует
  [правило проверки фронтенда](frontend-verification.md).
- Только E2E-тесты: файлы `*.e2e-spec.ts`, запуск `pnpm --filter api test:e2e`
  (конфигурация `packages/api/test/jest-e2e.json`). Unit-тесты `*.spec.ts` в `src/` не создаются.
- Проверяются только конечные маршруты: тест поднимает приложение и отправляет HTTP-запросы
  через `supertest`, утверждения делаются по статусу и телу ответа. Функции, сервисы,
  политики и прочий код без маршрута проверяются через маршруты, которые их используют;
  пока такого маршрута нет, тест для кода не создаётся.

## Размещение

- Все тесты лежат в `packages/api/test/<module>/`, где `<module>` — папка модуля
  в `packages/api/src/<module>/`.
- Строго один тестовый файл на один файл кода, объявляющий маршруты:
  `src/<module>/<name>.controller.ts` ↔ `test/<module>/<name>.controller.e2e-spec.ts`.
  Маршруты файла проверяются только в его парном тестовом файле;
  тестовый файл без парного файла с маршрутами не создаётся.

## Перед добавлением теста

1. Определите маршрут, поведение которого проверяете, и файл, который его объявляет.
2. Если парный тестовый файл существует, дополните его; иначе создайте по схеме выше.
